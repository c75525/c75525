# Authoring c75525

The homepage is the c75525 threshold at `/`; the conventional archive is secondary at `/archive/`. The threshold offers a random entry and an exact coordinate lookup. JavaScript-disabled visitors can use the archive; failed or empty location data leaves an archive link.

Opt a post in with front matter. Post titles are optional: omit the visible heading with `title: ""` (or `title: false`); the URL, content, and tube navigation still work.

```yaml
tube:
  world: c75525
  ring: 3
  object: 8
  branch_path: root/main
  coordinate: [2, 3]
  nav:
    inward: /jekyll/update/2026/04/17/hey-first-post.html
```

Supported directed edges: `clockwise`, `counterclockwise`, `inward`, `outward`, `branch`. Each currently has one optional destination. Omit unavailable directions. Destinations are exact Jekyll post URLs, without the deployment baseurl. The renderer suppresses self-links, missing/unpublished destinations, and destinations outside c75525.

Connections are authored, not inferred from dates or object numbers. Add reverse edges explicitly where appropriate. Ring chronology, unique coordinates, and semantic edge correctness are author responsibilities, not automatically enforced. `branch_path` is metadata, not a route generator.

One tube post may be designated as the nucleus with `core: true`. It renders fixed at the map center and is not part of a ring. Every other post belongs to a ring; a ring may contain any number of objects, with `object` controlling their around-ring order. The first sample post is the current core at `(0, 0)`. The third post remains a normal blog post. Tube posts use spatial arrows instead of chronological arrows; ordinary posts retain the existing navigation.

## Map geometry

The homepage map is generated in the browser from `tube-objects.json`, which is built from published post metadata. A `core: true` post is fixed at the center. Each distinct remaining `tube.ring` is one ellipse; every post on that ellipse is placed in ascending `tube.object` order. Authored navigation is intentionally not drawn as visible paths, so the map remains a spatial field rather than a topology diagram.

The map has a fixed viewBox and a fixed outer ellipse. When a new distinct ring appears, all present rings are repacked from the core to that outer ellipse, so ring spacing and object markers shrink rather than expanding the map footprint. Never use an object number from a different ring to position a post, and keep object numbers unique within each ring.
