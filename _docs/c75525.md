# Authoring c75525

The homepage is the c75525 threshold at `/`; the conventional archive is secondary at `/archive/`. The threshold offers a random entry and an exact coordinate lookup. JavaScript-disabled visitors can use the archive; failed or empty location data leaves an archive link.

Opt a post in with front matter:

```yaml
tube:
  world: c75525
  ring: 3
  object: 8
  branch_path: root/main
  coordinate: [2, 3]
  nav:
    inward: /jekyll/update/2026/04/17/hey-first-post.html
```

Supported directed edges: `clockwise`, `counterclockwise`, `inward`, `outward`, `branch`. Each currently has one optional destination. Omit unavailable directions. Destinations are exact Jekyll post URLs, without the deployment baseurl. The renderer suppresses self-links, missing/unpublished destinations, and destinations outside c75525.

Connections are authored, not inferred from dates or object numbers. Add reverse edges explicitly where appropriate. Assign older posts nearer the core and newer posts to outer rings; keep around-ring edges on the intended ring/branch. Ring chronology, unique coordinates, and semantic edge correctness are author responsibilities, not automatically enforced. `branch_path` is metadata, not a route generator.

The first and second sample posts are assigned ring 1, objects 1 and 2 with reciprocal clockwise/counterclockwise edges. Their coordinates are `(0, 0)` and `(1, 0)`. The third post remains a normal blog post. Tube posts use spatial arrows instead of chronological arrows; ordinary posts retain the existing navigation.

## Map geometry

The homepage map is generated in the browser from `tube-objects.json`, which is built from published post metadata. Each distinct `tube.ring` is one ellipse; each post is placed on its assigned ellipse in ascending `tube.object` order. Authored navigation targets are drawn as connections. It is therefore only accurate when ring, object, and nav front matter are accurate.

The map has a fixed viewBox and a fixed outer ellipse. When a new distinct ring appears, all present rings are repacked from the core to that outer ellipse, so ring spacing and object markers shrink rather than expanding the map footprint. Never use an object number from a different ring to position a post, and keep object numbers unique within each ring.
